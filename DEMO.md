```bash
cd sigsa-backend-new && npm run start:dev          # http://localhost:3000/api

# Backoffice
cd sigsa-backoffice && npm start                   # http://localhost:8100

# App móvil en el emulador
cd sigsa-frontend
ionic build && npx cap sync android && npx cap run android --target emulator-5554
```

```bash
~/Library/Android/sdk/platform-tools/adb shell \
  service call alarm 3 s16 "America/Argentina/Buenos_Aires"
```

## Preparar la base

```bash
npm run seed:demo -- --dry-run                     # ensayo, no escribe nada
npm run seed:demo -- --yes --demo-start=2026-09-15T10:00   # de verdad
npm run seed:demo:check                            # verificación
```

`--demo-start` ancla los eventos futuros: el push que suena en vivo se programa
**25 minutos después** de esa hora. Ponele la hora real de la reunión.

**El backend tiene que estar bajado** al sembrar: dos crons escriben cada minuto
y pelean con la transacción de borrado.

Conviene un respaldo antes:
`/Library/PostgreSQL/17/bin/pg_dump -h localhost -U postgres -Fc sigsa_db > sigsa_pre_demo.dump`

sin dispositivo.

hayas hecho a mano y reprograma los eventos futuros.

**El dashboard incluye el día de hoy**, así que lo que crees durante la reunión
aparece en los gráficos.

## Endpoints, por si hace falta probar a mano

```bash
# Login (devuelve access_token)
curl -s -X POST http://localhost:3000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@sigsa.demo","password":"Sigsa2026!"}'

# Con el token
curl -s http://localhost:3000/api/analytics/overview -H "Authorization: Bearer <token>"
```

Las rutas del backoffice (`/analytics/*`, `/users/all`, `/meds` paginado, los
catálogos, `/professionals/dashboard` y `/professionals/specializations`) exigen
rol `admin`: sin token dan 401 y con una cuenta común, 403.
